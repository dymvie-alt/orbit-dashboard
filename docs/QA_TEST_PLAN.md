## 🎯 1. מטרת התוכנית ורציונל מקצועי
Orbit Dashboard מיועד לשרת כמלווה שקט ורציף ("מעוף הציפור") עבור צוותי פיתוח, מפתחי AI ומשתמשי Claude Code / Antigravity.  
מאחר שמדובר בכלי מנטר שרץ ברקע על תיקיות קוד חיות, **רמת הסיכון התפעולי מחייבת אפס תקלות** — בדגש על שלמות הקוד של המשתמש (Zero-Footprint), שרידות מול פורמטים משתנים, ביצועי בזק ללא השהיות מערכת, ודיוק חסר פשרות בהצגת מצב הפרויקט.

| **RISK-4** | **קריסה על קבצים חסרים או פגומים:** פרויקט ללא `PHASE.md`, קובץ Markdown משובש, או מאגר ללא היסטוריית Git. | **בינוני** | גבוה | **Fault Injection & Resilience Testing:** בדיקת עמידות מול קבצי הרס ומבנים שבורים; הפעלת מנגנון Fallback אוטונומי. |
| **RISK-5** | **זליגת נתונים בין פרויקטים (Cross-Project Contamination):** מעקב אחרי פרויקט א' מציג נתונים מפרויקט ב'. | **גבוה** | נמוך | **Multi-Project Isolation Test:** בדיקת גיבוב MD5/SHA256 לכל נתיב פרויקט ושמירה במרחבים פיזיים נפרדים לחלוטין. |
| **RISK-6** | **הבהובי ריענון מעצבנים (Screen Flicker):** חלון הדפדפן במסך השני מרענן את כל העמוד כל כמה שניות. | **בינוני** | בינוני | **Soft-Sync DOM Patching:** דגימת JSON שקטה ברקע ועדכון אלמנטים נקודתי ללא `location.reload()`. |
| **RISK-7** | **עומס מעבד וסוללה (CPU Spikes):** סריקות רקע כבדות שמאטות את סביבת העבודה של המפתח. | **גבוה** | נמוך | **Performance Benchmark:** הגבלת זמן סריקה לפחות מ-200ms (בפועל: ~20ms). |

## 📋 3. פירוט תחומי הבדיקה ותרחישי הבדיקה (Test Suites)

### חבילה א': בדיקות שלמות ואי-התערבות (Zero-Footprint Integrity Test Suite)
* **TC-01 (Clean Tree Check):** יצירת פרויקט דמה, הפעלת סורק ה-Orbit, ואימות באמצעות Git שה-Working Tree נותר `clean` לחלוטין.
* **TC-02 (Directory Fingerprint):** חישוב Hash של כל הקבצים בתיקיית היעד לפני ואחרי סריקה — השוואת שוויון בינארי מלא.

### חבילה ב': בדיקות מנוע המתאמים והחוסן (Adapters & Resilience Suite)
* **TC-03 (Shraga Lifecycle Coverage):** אימות קריאת 7 שלבי שרגא, חילוץ מדויק של פאזה מ-`PHASE.md`, חילוץ משימות מ-`Plan.md`, טסטים מ-`reports/`, ופסקי דין (`Approved with conditions`) מ-`reviews/`.
* **TC-04 (Plan.md Checklists):** זיהוי רשימות תיוג `[x]` ו-`[ ]`, קביעת הפאזה הפעילה לפי המשימה הראשונה שלא סומנה.
* **TC-05 (Generic Git & Transparency):** סריקת פרויקט Git פשוט, אימות שאיבת קומיטים והופעה חובה של **באנר השקיפות המובנה**.
* **TC-06 (Malformed Input Fault Tolerance):** סריקת תיקייה ריקה, קובץ Markdown ללא כותרות, או `PHASE.md` עם טקסט שגוי — אימות שאין קריסת תהליך והמערכת מספקת תצוגה הגיונית.

### חבילה ג': בדיקות ביצועים וריבוי פרויקטים (Performance & Concurrency Suite)
* **TC-07 (Sub-200ms Benchmark):** מדידת משך הסריקה במילישניות — חובה לעמוד מתחת ל-200ms.
* **TC-08 (Dual-Project Isolation):** סריקה במקביל של שני פרויקטים שונים (Alpha ו-Beta), אימות שהנתונים והתיקיות המבודדות ב-`orbit/projects/` נפרדים לחלוטין.

### חבילה ד': בדיקות חוויית משתמש ו-Generative UI (UI & Ergonomics Suite)
* **TC-09 (100dvh Layout Budget):** אימות שקובץ ה-HTML מכיל את מחלקות ה-`100dvh` ואפס גלילת חלון.
* **TC-10 (Time-Machine Stepper):** אימות שניתן לעבור בין פאזות, לראות היסטוריה, ולחזור לפאזה הפעילה.
* **TC-11 (Live Ticking Clock):** אימות קיומו של מונה השניות המתעדכן בכל שנייה למניעת תחושת מסך קפוא.
* **TC-12 (About Modal Drawer):** אימות פתיחת חלון המידע (`?`) עם הטקסט הרשמי בעברית ובאנגלית וסגירתו במקש `Esc`.

## ✅ 4. שער אישור (Sign-off Criteria)
פאזה 4 תסומן כהושלמה ואושרה למעבר לפאזה 5 (השקה ואריזה) אך ורק כאשר:
1. 100% מתרחישי הבדיקה עוברים בהצלחה (Pass Rate: 100%).
2. כל מנגנוני ה-Zero-Footprint עומדים באימות מתמטי.
3. המשתמש מאשר את תוכנית הבדיקות והתוצאות.
